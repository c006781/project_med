## 1. Как устроено (кратко)

`BaseService` работает по `field_configs` сущности:

* **обычные поля** — копируются в модель (создание — `_get_creation_kwargs`, изменение —
  `_apply_simple_updates`); `required` — проверка обязательных;
* **заметки** (`is_note: '<поле_id>'`, `virtual`, `compute`, `source_attr`) — текст хранится в
  общей таблице `appointments_notes`, в записи — внешний ключ; одна заметка может стоять у
  многих записей (автодополнение, `get_or_create_note`);
* **вычисляемые** — `compute` (из связей, в Python) и `sql_compute` (подзапрос, например число
  фото у приёма);
* **связи** — жадная загрузка по конфигу, дети (`add_child`/`get_children`), проверка родителей;
* **файлы** (фото) — копирование в хранилище; удаление старых — после коммита, новых — при
  откате (`Database.session_scope` + обработчики `after_commit`/`after_rollback`);
* **фильтры** — дерево `and`/`or` → SQL; `fuzzy` — после запроса;
* **удаление** — запись + очистка заметок, которыми больше никто не пользуется.

## 2. Тесты

Старые тесты слоя данных (98 шт.) — до проверки 46 проходили, 43 падали при подготовке
(фикстуры по устаревшей схеме: `email` у пациента, `time` у приёма; сервисы без
`field_configs` — пациент писался с пустыми полями). Фикстуры и тесты обновлены (старое — в
комментариях): **113 проходят**. Новые тесты на найденное — на НАСТОЯЩЕЙ SQLite (коммит,
откат, удаление файлов): [`tests/test_services/test_data_layer_review.py`](../../tests/test_services/test_data_layer_review.py);
каждый проверен на коде до исправления (падает).

Полный набор: было 62 падения → **10** (CLI и сеть — не трогались). Тесты слоя данных проходят и с `SAWarning` как ошибкой.

## 4. Дальше

* Карта ключей `field_configs`: какой ключ где читается, неиспользуемые и противоречивые.
* Тесты общего механизма по каждому ключу (заметки, `compute`, `sql_compute`, жадная загрузка,

* Замеченное: фильтры по заметкам (`like`/`ilike`) не экранируют `%`/`_`;
  `sql_compute.result_type` нигде не читается.
