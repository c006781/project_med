## 1. Принципы

* **Один заход — один модуль**: всё, что нужно модулю (исправления, доработки, сверка,
  документация, тесты), делается в его заходе; заход заканчивается итоговой перепроверкой
  всего модуля (шаблон §2, п. 6). Порядок — от основы к окну, по фактическим импортам
  (`_dev/КАРТА.md` §2.1).
* Каждый заход — своя ветка `rework_work/<тема>` от `rework` (подходящая по смыслу уже есть — в ней; имена `rework-<тема>` ниже — читать так же); коммит и слияние — сам
  (`_dev/ДОГОВОРЁННОСТИ.md` «Как коммитить»).
* **Python 3.10 и 3.11:** код работает на обеих (CI и Windows — 3.10, Linux — 3.11): без
  возможностей 3.11+ (`tomllib`, `except*`, `typing.Self` …); перед выпуском — прогон на
  обеих машинах (§4, Ф3.7).
* **Экраны** (решение владельца 25.10.2026): везде подход RAD Studio (наборы данных) **с
  черновиками** — несколько правок, потом сохранить всё разом (мост `DraftsWriter`); в итоге
  всё переводится на него, страницы на черновиках (`draft_pages.py`) — переходные.
* **Старый слой** (решение владельца 25.10.2026): при замене — сведения из старого кода
  (причины, решения, подводные камни) в `_dev/docs/dev/СТАРЫЙ_СЛОЙ.md`; код **оставить**;
  удалить ненужное — в самом конце переработки (Ф4.8).
* **Живые запросы** (Яндекс.Диск, GitHub) и **push** — только с разрешения владельца на
  конкретную проверку (skill «Запреты»; режимы проекта их не снимают). Боевые запуски и
  работа с рабочей БД — разрешены (режимы «Боевые запуски», «База данных», бэкап перед
  записью в рабочую `clinic.db`).

## 2. Шаблон захода в модуль

1. Ветка; эталон тестов модуля (новая машина / давно не гонялись — проекта).
2. Чтение модуля и его `IMPLEMENTATION.md`; тесты на текущее поведение, если их нет.
3. Правка: находка → тест, падающий на старом коде → исправление; заменённый код —
   комментарием `↑ до <дата> (<номер>): <причина>`; новый и правимый код — формат skill п. 7.
4. Тесты модуля, затем проекта при сильной правке; без новых падений относительно эталона
   (Windows — 0 падений, 7 тестов CLI пропущены, ТД-3; Linux — 3 падения ТД-2).
5. **Синхронизация служебных файлов** — `IMPLEMENTATION.md` (журнал), `_dev/ПРОГРЕСС.md`,
   этот план (статус), `_dev/ОСТАЛОСЬ.md`, `tests/КАРТА_ТЕСТОВ.md`, `_dev/КАРТА.md`
   (структура); модуль переехал / удалён / стал скрыто импортироваться — `scripts/build_win.py`.
6. **Итоговая перепроверка модуля целиком** — тесты, ревью всего модуля (не только диффа),
   докстринги с примерами и типы нетронутых частей, `pyflakes`; повторять до чистого прохода.
7. Коммит (причина → правка → следствие) — код и служебные файлы вместе; слияние в `rework`.
