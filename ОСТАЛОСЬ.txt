1.1. [ИСПРАВЛЕНО 2026-10-21, ветка rework-yadisk] «Скачать БД с сервера» (Яндекс.Диск)
     не работало: в app/network/thread_network.py не была импортирована
     check_remote_file_exists. Импорт добавлен; DownloadThread.run() проверен
     с подменой клиента YaDisk (файл есть → finished(0), папка → понятная ошибка).
     Там же (app/network/ya_dop.py): скачивание в путь без папки ('clinic.db') падало
     на makedirs(''); загрузка и check_and_create_path (экран настроек) создавали только
     последнюю папку — у yadisk 3.x mkdir нет parents (аргумент молча отбрасывался),
     теперь makedirs. Вживую с настоящим Диском не проверялось.

1.1а. [ИСПРАВЛЕНО 2026-10-21, ветка rework-sync-service] Синхронизация через SyncService
     (командная строка, prepare_download/prepare_upload) брала путь на Диске из настроек
     как есть: при папке в настройках скачивание/выгрузка шли в папку, а не в файл БД;
     выгрузка без overwrite падала, если файл на Диске уже есть. Теперь
     remote_db_file_path() (дописывает имя файла, как MainWindow._correct_remote_path)
     и overwrite=True. Логика пути пока в двух местах — окно своё (см. п. 1.4).

1.2. clinic.py, стр. 618–619 — обращение к неопределённой переменной text_val.
     Строки стоят после raise (недостижимы), на работу сейчас не влияют, но это
     мёртвый ошибочный код. Не трогал (правило: код проекта не менять без нужды).

1.3. Подсказка типа на несуществующее имя PaginatedListPage
     (interfaces/gui/gui_window/widgets/delegate/image_delegate.py, стр. 219) — только
     в аннотации (# type: ignore), на работу не влияет.


1.4. Окно: у SyncMixin и UpdateMixin (interfaces/gui/gui_window/main_window.py)
     одноимённые _on_download_finished и _on_download_error; в MainWindow SyncMixin
     раньше — ошибки обновления показываются обработчиком синхронизации (заголовок
     «Ошибка» вместо «Ошибка загрузки»), путь download_update → «код <путь>».
     (Уточнено 2026-10-21: обычная установка идёт через UpdateApplier и download_finished

=====================================================================

6.1. Сортировка/фильтр по столбцам, которые считает программа или отдельный объект
     итогов (отметка, вычисляемые, итоги по подчинённым), — только когда загружено всё.

6.2. append() добавляет строку в конец ЗАГРУЖЕННЫХ строк (без догрузки всего).

6.3. total набора — число строк по словам источника, без новых несохранённых строк.

6.4. Строки, удалённые в БД другими, могут сдвинуть догружаемую порцию на одну строку
     (лечится refresh()).

6.5. Массовое действие при ошибке на одной строке останавливается: в черновиках уже
     сделанное отменяется одним шагом; в режиме «сразу в БД» уже записанное остаётся.

6.6. Поправка итогов «считает БД» на черновики — только для числа строк (count);
     для удалённой записи значение поля-ссылки (не родителя) известно, только если его
     меняли в черновике.

6.7. Черновики: один тип-родитель у типа; история отмены — снимками (для десятков
     тысяч черновиков стоит перейти на журнал); только в памяти (решение владельца);
     не потокобезопасно (поток интерфейса).

6.8. Движок миграций ждёт блокировку базы стандартные 5 с драйвера.
