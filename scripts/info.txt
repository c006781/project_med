Предполагается, что вы запускаете их из **корня проекта** (не из папки scripts), если не указано иное.

──────────────────────────────────────────────────────────────────────────────────────────────────────────
1. УСТАНОВКА ОКРУЖЕНИЯ
──────────────────────────────────────────────────────────────────────────────────────────────────────────

🔹 setup_dev.sh / setup_dev.bat
   Назначение: создание виртуального окружения venv_project_med и установка ВСЕХ зависимостей
               (production + development, включая pytest, coverage и т.п.).
   Особенности: при повторном запуске переспрашивает, пересоздавать ли venv.
   Использование:  ./scripts/setup_dev.sh   (Linux/macOS)
                   scripts\setup_dev.bat    (Windows)

🔹 setup_prod.sh / setup_prod.bat
   Назначение: создание venv и установка ТОЛЬКО production-зависимостей (из requirements.txt).
               Используется внутри Linux-дистрибутива, а также для CI/CD.
   Использование:  ./scripts/setup_prod.sh
                   scripts\setup_prod.bat

🔹 install_linux.sh
   Назначение: обёртка для setup_prod.sh внутри архива MedicalApp-linux.tar.gz.
               Автоматически переходит в каталог распакованного архива и запускает установку.
   Использование: (только внутри архива) ./install.sh

──────────────────────────────────────────────────────────────────────────────────────────────────────────
2. ЗАПУСК ПРИЛОЖЕНИЯ
──────────────────────────────────────────────────────────────────────────────────────────────────────────

🔹 run.sh / run.bat
   Назначение: активация виртуального окружения и запуск GUI (интерфейса main_gui_window.py).
               Предназначен для разработки, после того как окружение уже установлено.
   Использование:  ./scripts/run.sh          (Linux/macOS)
                   scripts\run.bat           (Windows)

🔹 run_linux.sh
   Назначение: запуск GUI внутри распакованного Linux-дистрибутива (после выполнения install.sh).
               Не требует повторной установки зависимостей.
   Использование: (внутри архива) ./run.sh

──────────────────────────────────────────────────────────────────────────────────────────────────────────
3. УПРАВЛЕНИЕ ЗАВИСИМОСТЯМИ
──────────────────────────────────────────────────────────────────────────────────────────────────────────

🔹 pip_freeze.sh
   Назначение: обновляет файл requirements.txt на основе текущего состояния pip freeze.
               Исключает пакеты, связанные с тестированием (pytest, coverage, pluggy и др.).
               Автоматически вызывается скриптом release перед коммитом.
   Использование:  ./scripts/pip_freeze.sh

──────────────────────────────────────────────────────────────────────────────────────────────────────────
4. РАБОТА С ВЕРСИЯМИ И РЕЛИЗАМИ
──────────────────────────────────────────────────────────────────────────────────────────────────────────

🔹 version.py
   Назначение: увеличивает номер версии в файле VERSION (корень проекта).
   Аргументы: patch, minor, major.
   Пример:     python scripts/version.py patch   # 1.0.0 → 1.0.1
               python scripts/version.py minor   # 1.0.1 → 1.1.0
               python scripts/version.py major   # 1.1.0 → 2.0.0
   Примечание: после изменения версии требуется создать git-тег (см. ниже).

🔹 release.sh / release.bat
   Назначение: ПОЛНЫЙ АВТОМАТИЧЕСКИЙ ЦИКЛ ВЫПУСКА РЕЛИЗА. Выполняет последовательно:
                1. Обновляет requirements.txt через pip_freeze.sh.
                2. Коммитит изменения зависимостей (если они есть).
                3. Увеличивает версию (patch/minor/major – передаётся аргументом).
                4. Коммитит файл VERSION.
                5. Создаёт аннотированный git-тег вида v<номер_версии>.
   Использование:  ./scripts/release.sh patch     (увеличить patch-версию и создать тег)
                   ./scripts/release.sh minor
                   ./scripts/release.sh major
   После выполнения скрипта необходимо вручную запушить тег и коммиты:
        git push origin main
        git push origin v1.0.1
   При пуше тега GitHub Actions автоматически соберёт релиз (Windows .exe и Linux.tar.gz)
   и опубликует его на странице Releases.

🔹 GitHub Actions (файл .github/workflows/release.yml)
   Назначение: автоматическая сборка и публикация релизов при создании тега вида v*.
   Собирает:
        - Windows: MedicalApp.exe (единый исполняемый файл)
        - Linux:   MedicalApp-linux.tar.gz (архив со скриптами установки и запуска)
   Результаты выкладываются на страницу https://github.com/ваш-аккаунт/project_med/releases
   Статичные ссылки на последний стабильный релиз:
        - Windows: https://github.com/ваш-аккаунт/project_med/releases/latest/download/MedicalApp.exe
        - Linux:   https://github.com/ваш-аккаунт/project_med/releases/latest/download/MedicalApp-linux.tar.gz

──────────────────────────────────────────────────────────────────────────────────────────────────────────
5. СБОРКА ДИСТРИБУТИВОВ (ЛОКАЛЬНАЯ)
──────────────────────────────────────────────────────────────────────────────────────────────────────────

🔹 build_win.py / build_win.bat
   Назначение: сборка Windows .exe с помощью PyInstaller.
   Требования: установленный pyinstaller (есть в requirements.txt) и Windows-среда.
   Результат:  dist/MedicalApp.exe
   Использование:  ./scripts/build_win.bat     (Windows)

🔹 build_linux.sh
   Назначение: создание архива MedicalApp-linux.tar.gz для распространения под Linux.
               Копирует исходники, скрипты install_linux.sh и run_linux.sh, а также requirements.txt и VERSION.
   Зависимости: tar, bash.
   Результат:  MedicalApp-linux.tar.gz (в корне проекта)
   Использование:  ./scripts/build_linux.sh   (Linux/macOS/WSL)

──────────────────────────────────────────────────────────────────────────────────────────────────────────
6. ДОПОЛНИТЕЛЬНЫЕ СОВЕТЫ
──────────────────────────────────────────────────────────────────────────────────────────────────────────

• Все .sh скрипты должны иметь права на выполнение. Если их нет, выполните в корне проекта:
      chmod +x scripts/*.sh

• Если вы используете Windows, убедитесь, что в PATH есть Python и Git Bash (для работы release.bat).

• Виртуальное окружение по умолчанию называется `venv_project_med` и располагается в корне проекта.
  При необходимости можно изменить имя, отредактировав переменную в скриптах.

• Для обновления зависимостей вручную (без выпуска релиза) используйте:
      source venv_project_med/bin/activate
      pip install --upgrade <package>
      ./scripts/pip_freeze.sh

• Файл VERSION хранит текущую версию приложения. Его изменение вручную не рекомендуется –
  используйте version.py или release.sh.

• Если вам нужно создать предварительный релиз (pre-release), используйте тег, содержащий суффикс `-pre` или `-rc`.
  Например: v1.2.3-pre. GitHub Actions автоматически пометит релиз как предварительный.

📌 ПРИМЕР ПОЛНОГО ЦИКЛА РАЗРАБОТКИ И ВЫПУСКА РЕЛИЗА:

1. Клонируйте репозиторий:
   git clone https://github.com/ваш-аккаунт/project_med.git
   cd project_med

2. Установите окружение разработки:
   ./scripts/setup_dev.sh

3. Активируйте окружение и запустите приложение:
   source venv_project_med/bin/activate
   ./scripts/run.sh

4. Внесите изменения в код, протестируйте.

5. Когда всё готово к выпуску, выполните:
   ./scripts/release.sh patch   # (или minor/major)

6. Запушьте изменения и тег:
   git push origin main
   git push origin v1.0.1

7. Дождитесь завершения GitHub Actions (около 3-5 минут). Релиз появится по адресу:
   https://github.com/ваш-аккаунт/project_med/releases

8. Скачайте собранные артефакты и распространяйте.
