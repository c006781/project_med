## 1. Как работает сейчас

**Данные (дерево):** пациент → приём → фото. Заметки (`appointments_notes`) привязаны к
пациенту и приёму как поля (`is_note` в `field_configs`).

**Экраны:** фрейм 1 — список пациентов (`PatientListPage`, одна таблица); фрейм 2 —
`AppointmentPhotoFrame` (таблица приёмов + таблица фото выбранного приёма).

**Ключи в `DraftRegistry`:**

| Ключ | Что |
|---|---|
| `{тип}:{id}:draft` | изменённая строка (`{"dto": model_dump}`) |
| `{тип}:{id}:{подсистема}` | черновик компонента (например, `appointment:123:photos`) |
| `__new__:{тип}:{temp_id}` | новая строка, `temp_id < 0` |
| `__deleted__:{тип}:{id}` | строка помечена на удаление |
| `__status__:{тип}:{id}` | `own` / `child` / `both` — есть изменения у себя / у потомков |
| `__counter__:{тип}:{parent_id}` | сколько потомков с изменениями |
| `__parent_counter_inc__:{тип}:{temp_id}` | служебный ключ балансировки счётчика |

**Статусы:** `DraftTreeMixin.mark_own_change / clear_own_change / mark_child_change`
меняют статус строки и `±1` в счётчике родителя, статус поднимается вверх
(`_propagate_status_up`). Родитель строки — через переопределения страниц
(`_get_parent_id`, `_get_parent_entity_type`, `_get_child_ids`).

**Сохранение:** таблица — одной транзакцией (`_save_all_changes_impl_session`): новые
строки (карта `temp_id → id`), изменения дочерних, изменённые, удалённые. Фрейм 2
(`_save_all`) — приёмы, затем фото, **двумя транзакциями**.

## 2. Требования (владелец, 2026-10-15)

1. Несколько таблиц, связанных деревом; количество таблиц и глубина вложенности —
   **динамические** (не зашиты в код страниц).
2. Можно вносить изменения в разных таблицах и на разных фреймах, переходить между
   фреймами и строками, возвращаться — изменения копятся и **сохраняются разом**.
   Пример: изменили строку на фрейме 1 → фрейм 2, изменения в двух таблицах → назад на
   фрейм 1, другая строка → снова фрейм 2, изменения … → сохранить.
3. Уже изменённую ветку можно **изменять повторно** (черновик дополняется/заменяется).
4. Можно **сохранять отдельные ветки**.
5. «Сохранить» — **вопрос пользователю: сохранить всё или текущее**. В КОДЕ объём
   сохранения задаётся гибко (уточнение владельца 2026-10-15), см. §2.1.
6. Сохранение ветки, у которой родители **новые (не в БД)**: предупредить; при согласии
   сохранять **начиная от родителей** (цепочка новых родителей + ветка).
7. Родитель помечен на удаление — удаляется **вся ветка** (с черновиками детей). Перед
   сохранением — **подтверждение со списком веток под удаление**. Сделать так, чтобы
   политику можно было поменять позже (стратегия, а не зашитое поведение).
8. Черновики — **только в памяти**; при закрытии с несохранёнными изменениями — вопрос
   (сохранить / отменить).

### 2.1 Объём сохранения (уточнение владельца 2026-10-15)

Объём = **цель** × **направления**; любые сочетания задаются в коде.

**Цель — что считать «текущим»:**

| Цель | Что это | Пример |
|---|---|---|
| строка | выбранная строка как часть ветки (один узел дерева) | выбранный приём |
| выборка фрейма | набор строк фрейма — несколько веток | все приёмы пациента на фрейме «Приёмы и фото» |
| всё | все черновики реестра | кнопка «Сохранить всё» |

**Направления — флаги, сочетаются свободно:**

| Флаг | Что входит |
|---|---|
| `SELF` | изменения самих узлов цели |
| `DESCENDANTS` | изменения всех потомков узлов цели |
| `ANCESTORS` | изменения предков узлов цели (только сами предки — без их других детей) |

Примеры: «только текущее» = `SELF`; «текущее и дочернее» = `SELF | DESCENDANTS`;
«родители и текущее» = `ANCESTORS | SELF`; «родители, текущее и дочернее» =
`ANCESTORS | SELF | DESCENDANTS`; «только дети» = `DESCENDANTS`.

**Обязательные правила поверх флагов** (не зависят от выбранного объёма):
* новый (не в БД) предок узла, попадающего в сохранение, нужен для внешнего ключа —
  если `ANCESTORS` не задан, пользователя предупреждают и при согласии цепочка новых
  предков добавляется (треб. 6); без согласия — сохранение отменяется;
* узел под удалением удаляется вместе со всем поддеревом — его поддерево добавляется в
  план, удаление подтверждается списком веток (треб. 7, политика — стратегия).

**Набросок API** (имена предварительные):

```python
class SaveScope(enum.Flag):
    SELF = enum.auto()
    DESCENDANTS = enum.auto()
    ANCESTORS = enum.auto()
    BRANCH = SELF | DESCENDANTS
    FULL_PATH = ANCESTORS | SELF | DESCENDANTS

# цель — набор узлов (тип, id); строка — один узел, фрейм — его выборка, всё — None
plan = drafts.build_plan(targets={('appointment', 12)}, scope=SaveScope.BRANCH)
plan.new_ancestors      # новые предки, которых нет в объёме -> предупреждение
plan.deleted_branches   # ветки под удаление -> подтверждение
drafts.save(plan, session)   # одна транзакция; новые сверху вниз, удаления снизу вверх

drafts.build_plan(targets=None, scope=SaveScope.SELF)   # «сохранить всё»
drafts.build_plan(targets=frame.selection_nodes(), scope=SaveScope.ANCESTORS | SaveScope.SELF)
```

План строится без БД и без GUI (чистая функция от реестра и описания дерева) — его
легко тестировать; GUI только задаёт цель/флаги и показывает вопросы.
