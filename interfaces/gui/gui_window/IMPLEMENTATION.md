# Окно программы (`interfaces/gui/gui_window`) — заметки о реализации

> Для разработчиков: что делает модуль, как устроен и почему. Заведён 2026-11-07 с экраном настроек;
> раздел главного окна дополнит заход по `main_window.py`.
> Находки экрана настроек — `ST<n>`.

## 1. Экран настроек (`pages/settings_page.py`)

| Что | Где |
|---|---|
| Страница, две вкладки | `SettingsPage` |
| Какое поле какой настройке соответствует | `_bind_settings_fields` |
| Чтение и запись значений | `_load_settings`, `_sawe_new_config` (имя с опечаткой, им пользуются тесты) |
| Сохранить и применить | `_save_settings` → `create_config_applier().apply_changes` → `on_settings_changed` окна |
| Проверка Диска | `TokenCheckThread`, `PathCheckThread`, `remote_folder_of` |
| Уборка | `_on_clean_photos_clicked`, `_on_clean_rows_clicked`, `confirm_cleanup` |

### 1.1 Типы значений

Значения читаются и пишутся по таблице `_bind_settings_fields`; тип задаёт вид поля: текст — `str`
без пробелов по краям, спин — `int`, флажок — `bool`, уровень — строка из списка, выбор —
`currentData`. Новое поле — создать виджет и добавить строку в таблицу.

Менеджер настроек намеренно оставляет непереводимую строку как есть (`app/config/IMPLEMENTATION.md`
§4.z), поэтому она доходит до экрана. Экран не падает: в поле показывается умолчание, в журнал —
предупреждение, а в файл значение попадёт, только если пользователь нажмёт «Сохранить». Флажки читают
строки через `to_bool` (`'on'` — истина, `'off'` — ложь, остальное — ложь).

Пустая папка копий базы при сохранении заменяется умолчанием, и поле это показывает.

### 1.2 Проверка Диска

Потоки всегда отправляют `result`: без этого исключение в `run` оставляло кнопку выключенной. Функции
`check_token`, `check_and_create_path` сами ошибок почти не бросают, но клиент создаётся и закрывается
вне их перехвата.

В поле «Удалённый путь БД» может быть и папка, и файл базы; по умолчанию там файл. Кнопка проверяет
папку (`remote_folder_of`, то же правило расширений, что у `remote_db_file_path`). Отсутствующая папка
создаётся без вопроса: так было и раньше, хотя старое описание обещало «предлагает создать».

При выходе из программы страница ждёт идущие проверки (`wait_check_threads`, по 3 с на поток; подключено
к `aboutToQuit`): поток, уничтоженный на ходу, роняет процесс. Поток не прерывается: прерванный посреди
запроса он может оставить интерпретатор в плохом состоянии. Не успел — то же сообщение Qt, что и раньше.

### 1.3 Уборка

Два действия на готовых методах, оба по схеме «список → подтверждение → удаление подтверждённого»:

| Кнопка | Метод сверки | Удаление | Что удаляет |
|---|---|---|---|
| «Очистить фото без ссылок» | `PhotoService.check_storage` | `clean_storage` | файлы папки фото без строки файла; пустые папки `app_*` |
| «Очистить записи без ссылок» | `TableEvents.find_unused` | `delete_unused` | строки таблиц «только используемые»: заметки, строки файлов (файл — после коммита) |

Список показывается целиком в прокручиваемом поле (`confirm_cleanup`), по умолчанию выбрана отмена.

Уборка не запускается (`_cleanup_blocked_reason`), если:
* файла базы нет — открылась бы новая пустая база, и все фото оказались бы «без ссылок»;
* путь к базе или папка фото в форме не сохранены — пользователь видел бы одни пути, а сверка шла бы по другим;
* есть несохранённые черновики — их ссылки ещё не в базе.

Ограничение: если сохранён путь к другой, существующей базе, а папка фото прежняя, все её файлы будут в
списке как «без ссылок». Защита — подтверждение: в окне указаны база и папка и число файлов.

### 1.4 Настройки, которые применяет не применитель

`DRAFT_MOVED_RULE`: блок `drafts` в `SETTINGS_BLOCKS`, применитель ничего не делает. Смену видит главное
окно в `on_settings_changed` (`'drafts' in changed_blocks`). `WORD_DOCUMENTS_PATH` в блоки не входит:
значение читается в момент импорта.

### 1.5 Не менялось намеренно

`_on_tab_changed` не подключён и не работает (`content_layout`, `about_title` остались от прежней
раскладки): оставлен как есть, с пометкой в докстринге.
