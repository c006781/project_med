6. ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ НОВОГО (сделано так сознательно)
=====================================================================

6.1. Сортировка/фильтр по столбцам, которые считает программа или отдельный объект
     итогов (отметка, вычисляемые, итоги по подчинённым), — только когда загружено всё.

6.2. append() добавляет строку в конец ЗАГРУЖЕННЫХ строк (без догрузки всего).

6.3. total набора — число строк по словам источника, без новых несохранённых строк.

6.4. Строки, удалённые в БД другими, могут сдвинуть догружаемую порцию на одну строку
     (лечится refresh()).

6.5. Массовое действие при ошибке на одной строке останавливается: в черновиках уже
     сделанное отменяется одним шагом; в режиме «сразу в БД» уже записанное остаётся.

6.6. Поправка итогов «считает БД» на черновики — только для числа строк (count);
     для удалённой записи значение поля-ссылки (не родителя) известно, только если его
     меняли в черновике.

6.7. Черновики: один тип-родитель у типа; история отмены — снимками (для десятков
     тысяч черновиков стоит перейти на журнал); только в памяти (решение владельца);
     не потокобезопасно (поток интерфейса).

6.8. Движок миграций ждёт блокировку базы стандартные 5 с драйвера.

6.9. Миграция, которая импортирует модуль, не используемый остальной программой, в exe
     упадёт — такой модуль добавить в скрытые импорты scripts/build_win.py.
