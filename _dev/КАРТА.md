## 1. Что это

Настольная программа клиники: пациенты, приёмы, фото, заметки; база SQLite, синхронизация
файла базы через Яндекс.Диск, автообновление через GitHub Releases, импорт из Word.
Python 3.11 (Linux) / 3.10 (Windows и CI), SQLAlchemy 2, Pydantic 2, PySide6. Ветка
разработки — `rework` (темы — `rework-<тема>`). Окружения машин — `_dev/ДОГОВОРЁННОСТИ.md`
«Окружение».

## 2. Слои и связи

```
точки входа: main_gui_window.py · main_cli.py · pars_start.py
        │
interfaces/gui (PySide6: окно, страницы, виджеты)      interfaces/cli (click)      parsers/ (Word)
        │                                                   │                          │
        └──────────────┬────────────────────────────────────┴──────────────────────────┘
                       ▼
app/dependencies.py — сборка: get_db(), get_*_service() (lru_cache, реестр поставщиков)
                       ▼
app/services ──► app/repositories ──► app/database (Database, модели, миграции)
    │                                          ▲
    ├─ app/dto (DTO, field_configs) ◄──┐       │
    ├─ app/utils/filtering             │       │
    ├─ app/utils/file_deletions,       ├── app/schema (описания таблиц: модели, DTO, конфиги)
    │  deferred_actions, virtual_fields│
    └─ app/exceptions                  └── app/tables (описания для наборов данных)

новый слой (пилот):  app/utils/dataset(+_qt) · app/utils/drafts(+_qt) · app/dataset_app
старый слой окон:    app/draft (DraftRegistry) · interfaces/gui/…/pages/paginated_* , dynamic_*
сеть:                app/network (Яндекс.Диск) ◄─ app/services/sync_service, окно (SyncMixin)
обновления:          app/updater ◄─ окно (UpdateMixin)
настройки, журналы:  app/config · app/utils/logger
```

### 6.1 Принципы

* Порядок — **от основы к окну**; внутри — по зависимостям (§6.2).
* Каждая задача — своя ветка `rework-<тема>` от `rework`; коммит и слияние — сам
  (`_dev/ДОГОВОРЁННОСТИ.md` «Как коммитить»).
* «Решение владельца» — задача ждёт ответа (`_dev/ТЕХДОЛГ.md`), до ответа не начинать
  (остальное — делать).
* **Python 3.10 и 3.11:** код должен работать на обеих (CI и Windows — 3.10, Linux — 3.11):
  без возможностей 3.11+ (`tomllib`, `except*`, `typing.Self` …). Перед выпуском (Ф3) — полный
  прогон на обеих машинах.
* **Экраны** (решение владельца 25.10.2026): на наборах данных **с черновиками** — несколько
  правок, потом сохранить всё разом (мост `DraftsWriter`). Что делать со страницами на
  черновиках (`draft_pages.py`) — решить после Ф1 («когда разберёмся со всей внутрянкой»),
  контрольная точка Ф2.0.
* **Старый слой** (решение владельца 25.10.2026): при замене экрана сведения из старого кода
  (причины, решения, подводные камни из комментариев и журналов) — продублировать в файл
  `_dev/docs/dev/СТАРЫЙ_СЛОЙ.md`; код **оставить** (может понадобиться); удалить ненужное —
  в самом конце переработки (Ф4.8).
* **Живые запросы** (Яндекс.Диск, GitHub) и **push** — только с разрешения владельца на
  конкретную проверку: режимы проекта их не снимают (skill «Запреты»). Боевые запуски и
  работа с рабочей БД — разрешены (режимы «Боевые запуски», «База данных»).

**Шаг любой задачи (шаблон):**
1. Ветка; эталон тестов модуля (новая машина / давно не гонялись — проект).
2. Чтение модуля и его `IMPLEMENTATION.md`; тесты на текущее поведение, если их нет.
3. Правка: находка → тест, падающий на старом коде → исправление; заменённый код —

5. `IMPLEMENTATION.md` (журнал), `_dev/ПРОГРЕСС.md`, `tests/КАРТА_ТЕСТОВ.md`, эта карта;
