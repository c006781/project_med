## Как коммитить

Режим «Как коммитить» (25.10.2026) — так коммиты делались в этом проекте; отличается от
skill п. 4 (там — поимённо и коммит путями).

1. **Ветка.** Правка — в ветке темы: `git checkout -q -b rework-<тема>` от `rework`
   (только `rework` и `rework-*`, режим «Ветки»).
2. **Что изменено.** `git status --short` перед добавлением. Неотслеживаемые и изменённые
   файлы не мои (файлы пользователя в корне, бэкапы, копии конфигов) — не добавлять.
   В индексе ничего чужого: `git diff --cached --name-only` пуст до моего `git add`.
3. **Добавление — папками правки:** `git add <папка> <папка> <файл>` (например,
   `git add app tests _dev`) или `git add -A <папка>` (вместе с удалёнными и новыми
   файлами в ней). Нельзя: `git add -A` / `git add .` для всего корня, `git commit -a`.
   Если в добавляемой папке есть изменённые пользователем файлы — эту папку добавлять
   поимённо, без них, и сказать о них в ответе.
4. **Секреты и данные** не попадают: их закрывает `.gitignore` (`*.env`, `*.db`,
   `*.msgpack`, `photos*/`, `.coverage`); в выводе `git status --short` их быть не должно —
   есть → не коммитить, сказать.
5. **Коммит:** `git commit -q -m "<заголовок>" -m "<тело>"` (сообщение — как в skill п. 4)
   — весь индекс (в нём только моё, п. 2–3).
   Хуки не обходить (`--no-verify` нельзя); упал хук — сообщить.
6. **Проверка:** `git show --stat HEAD` — состав коммита совпал с задуманным (только мои
   файлы); `git -c core.quotepath=off status --short` — осталось только чужое
   (неотслеживаемое не моё). `core.quotepath=off` — иначе русские имена выводятся кодами.
7. **Когда:** после каждого законченного шага (подзадачи) с проверкой — тесты без новых
   падений относительно эталона; при проходах ревью — коммит на каждый проход.
8. **Слияние** (режим «Ветки»): тема закончена — `git checkout -q rework` →
   `git merge -q --no-ff rework-<тема> -m "Слияние rework-<тема>: <кратко>"`; конфликт —
   не решать наугад: показать и спросить. Ветку темы не удалять. Push — никогда сам.
