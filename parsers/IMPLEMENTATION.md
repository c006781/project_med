# parsers — импорт из Word: как устроено и почему

Заведён 2026-10-25 (заход М1, `_dev/ПЛАН.md` Ф1.1). Поведение для пользователя — инструкция
«Парсинг файлов» (`docs/`); тесты — `tests/test_parsers/`.

## 1. Что делает

`word_importer.py` читает `.docx` (python-docx) и записывает пациента и его приёмы в базу
через сервисы приложения (`PatientService`, `AppointmentService`, `PhotoService`).

Формат документа (образцы — `doc/`, вне git):
* **Шапка** — первая непустая строка до первой таблицы:
  `Фамилия Имя [Отчество] [Год[г]] [Телефон] [Контакт / описание]`
  (`PatientInfoExtractor`).
* **Таблицы** — первая строка — заголовки, далее строки приёмов; несколько таблиц
  объединяются. Столбцы сопоставляются полям приёма по заголовкам (`WordFileParser`):
  сначала по `title` из `appointment_service.get_field_metadata()`, затем по синонимам
  (`FIELD_SYNONYMS`) — только для даты и фото, затем столбец фото — по рисункам в заголовке.
* **Фото** — рисунки в ячейках столбца фото, сохраняются во временную папку и копируются
  `PhotoService` в хранилище.

Цепочка вызовов:
* окно — `MainWindow._start_parsing` → `ParsingThread` → `batch_parse(specific_files=None)`;
  статусы файлов — `ParsingProgressDialog.update_file_status`, итоги — `format_results`;
* командная строка — `pars_start.py --folder <папка> [--files а.docx,б.docx]
  [--update_existing_patient]` → `pars_start_args` (argparse) → `pars_start` →
  `batch_parse`; итоги печатаются (`format_results`);
* `batch_parse` — без `specific_files` берёт все `.docx` папки без `~$…` и без успешно
  обработанных по журналу (W7); по файлу: своя транзакция (`db.session_scope()`),
  `parse_one_file`, строка в журнале `<папка>/logs_parser/parser.log`. Возвращает всегда пару
  `(результаты, папка журнала | None)`.

Результаты: `total`, `success`, `failed`, `success_files`, `error_files` (`{file_name, error}`,
`error` — исключение), `warnings` (`{file_name, warning}` — предупреждения успешных файлов, W2);
у `pars_start` ещё `log_path` — путь к `parser.log`.

Журнал `parser.log` — строки `!!>>\tзапуск\tвремя файла\tимя\tsuccess|failed\tсообщение`
(у `success` в сообщении — предупреждения через «; »); повторный запуск пропускает файлы со
статусом `success` (`get_successful_files_from_log`). Многострочное сообщение об ошибке
разрывает строку журнала — поэтому метка `!!>>` в начале каждой записи.

Колбэк `progress_callback_update(file_name, status, message)` — все три строки (W10):
`processing` / `success` (предупреждения или пусто) / `failed` (текст ошибки).

Временные рисунки — в своей папке `tempfile.mkdtemp(prefix='project_med_docx_')` на файл,
удаляется в `parse_one_file` в любом случае (W8).

`pars_start.py`: папка — только `--folder` (обязательна; по умолчанию папки нет — Ф1.1.7,
умолчание согласовать с владельцем); аргументы командной строки главнее параметров вызова
`pars_start_args`.

## 2. Решения и подводные камни

* Один файл — одна транзакция: ошибка в файле откатывает всё по нему (пациент, приёмы, фото
  в БД); файлы фото, уже скопированные в хранилище, при откате остаются (так у `PhotoService`).
* Дата рождения пациента обязательна (`app/schema/clinic.py`, `required=True`): шапка без
  года — пациент не создаётся, файл — `failed`.
* **Телефон** (решение владельца 2026-10-25, W2): только номера РФ — 11 цифр с `7`/`8` или
  10 цифр, начинающихся с 3, 4, 8, 9. Нераспознанный (городской без кода, добавочный,
  другие страны) не записывается, пациент импортируется, пользователю — предупреждение
  (`normalize_patient_dto(warnings=…)`). Городские номера без кода — обсудить с владельцем
  (`_dev/ПЛАН.md` Ф1.1.3).
* **Код города из 4–5 цифр** (W3) виден только по записи: скобки `8 (3842) …` или отдельная
  группа `8 3842 …`. Номер слитно (`83842123456`) — выводится обычным видом
  `+7 (384) 212-34-56`: по одним цифрам код не определить. Поэтому шапка хранит телефон как
  в тексте (W5), а цифры выделяет `normalize_phone`. Маска ввода телефона в окне
  (`input_mask='+7 (999) 999-99-99'`, `app/schema/clinic.py`) рассчитана на трёхзначный код:
  номер `+7 (3842) 12-34-56` при правке в окне может исказиться — смотреть в М21 (экраны).
* **Шапка** (W5, W6): отчество — слово не с цифры, `+`, `(`; год — ровно 4 цифры, за ними не
  цифра (иначе 11 цифр телефона давали год 8999); пометка `г` / `г.` — только не начало
  слова («2012 галина» — описание «галина»). Неоднозначность остаётся: без отчества первое
  слово контакта («Иванов Иван Анна») станет отчеством — как и раньше.
* `WordFileParser._clean_text` повторяет старый `normalize_text` (без W1): тексты ячеек
  потом всё равно проходят `normalize_text`, заголовки — `normalize_match`. Дублирование —
  Ф4.6.
* **Ограничения** (известны, не меняются без решения владельца):
  * строка таблицы без текста пропускается, даже если в ней есть рисунок (`_is_row_empty`);
  * двузначный год даты — всегда 20ГГ (`14.03.99` → 2099);
  * запасной поиск даты берёт первый столбец слева, где есть «дата» (в шаблоне дата —
    первая; «Рекомендации и дата сл. приёма» правее);
  * файл, однажды импортированный успешно, больше не обрабатывается (журнал), даже если
    документ потом дополнили — нужно убрать его строку из `parser.log` или переименовать
    (тогда приёмы добавятся заново, с дублями — ТД-8);
  * `find_matching_patient` перебирает всех пациентов базы на каждый файл.
* **ТД-8** (`_dev/ТЕХДОЛГ.md`): `update_existing_patient=True` — падает на описании в шапке
  (`Patient.description_text` нет у ORM) и по смыслу ничего не обновляет (совпадение по всем
  полям). Тест `test_td8_…` — `xfail(strict=True)`.
