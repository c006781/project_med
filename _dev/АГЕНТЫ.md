# Параллельные агенты: территории и ход работы

> Реестр ведёт **оркестратор** (основная сессия). Исполнитель этот файл только читает, а
> свой ход работы пишет в `_dev/agents/<М>.md` — **в основной копии**
> (`C:\Git\project_med\_dev\agents\`), а не в своей worktree: так файлы видят все.
> Режим — `_dev/ДОГОВОРЁННОСТИ.md` «Параллельные агенты» (2026-10-25).

## Правила

1. **Территория** — файлы и папки из таблицы ниже. Править можно только свою. Нужна правка
   вне территории (общий код, чужой модуль, `tests/conftest.py`, `pytest.ini`,
   `requirements*.txt`) — **не делать**: описать в своём файле («Нужно вне территории») и в
   отчёте; решает оркестратор.
2. **Общие служебные файлы** (`_dev/ПЛАН.md`, `ПРОГРЕСС.md`, `ОСТАЛОСЬ.md`, `ТЕХДОЛГ.md`,
   `ИДЕИ.md`, `КАРТА.md`, `ДОГОВОРЁННОСТИ.md`, `АГЕНТЫ.md`, `tests/КАРТА_ТЕСТОВ.md`) — не
   править; готовые строки для них — в разделе «Для служебных файлов» своего файла.
   `IMPLEMENTATION.md` своего модуля — вести самому (журнал «дата — что — зачем»).
3. **Свой файл** `_dev/agents/<М>.md` — обновлять после каждого шага: что делаю сейчас, что
   сделано (с коммитами), находки, вопросы владельцу, нужное вне территории, строки для
   служебных файлов. Чужие файлы `_dev/agents/*.md` — только читать.
4. **Git** — только в своей worktree и своей ветке: коммиты (как в `ДОГОВОРЁННОСТИ.md`
   «Как коммитить», добавление — путями своей территории и своего `IMPLEMENTATION.md`);
   нельзя: push, merge, rebase, reset, stash, checkout других веток, операции с worktree.
5. **Слияние** — только оркестратор: дифф, полный прогон, по одной ветке; общие служебные
   файлы — в коммите слияния.
