### В-3. Черновики: сохранение записи, перенесённой в удалённую новую (ОСТ п. 5.6)

Пример: фото перенесли к новому приёму, потом этот новый приём пометили на удаление.
* «Сохранить» — фото поглощается целиком: не записываются ни перенос, ни другие правки фото
  (диалог предупреждает «изменения будут потеряны»).
* «Отменить» новый приём — фото возвращается к прежнему приёму, остальные его правки
  сохраняются.

Варианты: **А** — сделать сохранение как отмену (фото — к прежнему приёму, прочие правки
записать); **Б** — оставить как есть.

Рекомендация: А (меньше потерь данных).

Ответ (2026-10-26, частично):
* Сохраняется всё разом (и строка «откуда», и строка «куда») — выполнять по порядку:
  сначала перенос, потом удаление.
* Надёжнее — перестроить хранение фото: файл лежит в папке, в БД — ссылка на него; на один
  файл может быть несколько ссылок; файл удаляется, только когда ссылок на него не
  осталось, и то с предупреждением. Записано в `ОСТАЛОСЬ.md` п. 5.6.

Уточнить: (1) «перенос, потом удаление» — фото, перенесённое к удалённому новому приёму,
удаляется вместе с ним (как сейчас, но с ясным порядком), а при новом хранении файл
остаётся, если на него есть другие ссылки, — так? (2) перестройку хранения — в какой заход
(предлагаю отдельной задачей в М8 `app/database` + М11 `app/services`, вместе с FD9 / FD10)?

### В-4. Удаление файла «после коммита», когда транзакции уже нет (FD10, ОСТ п. 5.7)

`schedule_deletion` с режимом «после коммита» при неактивной сессии удаляет файл сразу, хотя
коммита уже не будет. Для режима «при откате» в той же ситуации файл не удаляется.

Варианты: **А** — не удалять (как «при откате»), записать предупреждение в журнал; **Б** —
оставить немедленное удаление.

Рекомендация: А (безопаснее: файл не пропадёт без сохранения).

Ответ (2026-10-26): «давай подумаем вместе» — обсуждаем. Разбор: в SQLAlchemy 2.0 сессия
неактивна (`is_active=False`) только после ошибки `flush` внутри транзакции — она будет
откачена, строка в БД останется, а файл, на который она ссылается, уже удалён. Вызывающих
сейчас — сервисы (`_delete_file_field`, `_del_file`, `app/services/services_all.py`).
Варианты на обсуждение: А — не удалять, предупреждение в журнал; Б — ошибка (удаление в
сломанной транзакции — ошибка вызывающего); В — с новым хранением фото (В-3) удаление
«после коммита» = проверка ссылок после коммита, файл без ссылок — удалить, иначе
оставить; неактивная сессия — ничего не удалять.
