# Обновление в фоне и колокольчик уведомлений (ПЛАН Ф2.1.9, ОСТ п. 5.31, В-42)

Сформировано 2026-11-07. Код ещё не менялся, это проект для исполнителя. Решение владельца — В-42, вариант Б.

## Что просил владелец

* Обновление скачивается в фоне, работать можно. После скачивания — кнопка, которая ставит уже скачанное.
* Не отдельный всплывающий попап, а кнопка-колокольчик со списком уведомлений. Список можно свернуть, чтобы не мешал.
* Перед установкой проверить несохранённые изменения: они не должны пропасть.
* Скачал, закрыл и открыл программу — повторно не скачивать: версия и файл записаны в системном информационном файле.
* После установки удалить установочные файлы этой версии и предыдущих, если остались.

## Как сейчас (вершина b82f2b9)

`UpdateMixin._on_update_available` (вопрос) → `_install_update` (вопрос о несохранённом, модальный `UpdateProgressDialog`) →
`AppUpdater.apply_update_from_release` → `UpdateApplier.start` → `UpdateDownloader` (`.part`, размер, SHA-256, `os.replace`) →
`_on_downloaded` → `_apply_update` (скрипт и `sys.exit`). `_on_update_download_progress` пишет в общий `progress_bar`, его же
использует обмен с Диском.

## app/updater.py (логика без Qt — функциями)

* `UPDATE_READY_FILE = '.update_ready.json'`. Префикс `.update_` уже запрещён манифестом (`validate_manifest_path`), а
  `_LINUX_WORK_DIR_RE` (`^\.update_\d+$`) его не заденет.
* Папка — одна функция: Linux `get_install_root()`, иначе `get_app_dir()` (сейчас выражение внутри `UpdateApplier.start`).
* `DownloadedUpdate` (dataclass): `version`, `file_name`, `sha256`, `size`. В файле только имя, без пути: установку можно
  переносить и переименовывать (требование Ф1.5.5). Токена и адресов в файле нет.
* Запись атомарно (`.tmp` + `os.replace`). Чтение устойчиво: битый JSON, не те поля, имя не по шаблону
  `^MedicalApp_new_\d+(\.exe|\.tar\.gz)$` (путь наружу) — значит «файла нет», без исключения.
* `find_ready_update`: версия новее текущей (`is_newer_version`), файл есть, размер совпал. Хеш здесь не считать: это старт окна.
* Перед установкой — полная сверка `file_sha256`. Не совпал: файлы удалить, `download_error` с просьбой скачать заново.
* `remove_update_files(folder, keep=None)`: только файлы по шаблону, их `.part` и информационный файл.
  **Никогда не удалять `sys.executable`:** на Windows новая версия запускается как `MedicalApp_new_<t>.exe --rename-to …`
  (`main_gui_window.handle_rename_argument`).
* Очистка при старте: версия в файле не новее текущей (установлено или устарело) — удалить всё. `.part` старше часа — удалить
  (`UPDATE_PART_STALE_SEC`): вторая копия программы не определяется, свежий `.part` может быть ещё в работе. Файлы без
  информационного файла при старте не трогать, их уберёт следующее скачивание.
* `UpdateDownloader`: `cancel()` — `threading.Event`, проверка в цикле `_download_file`; при отмене `.part` удаляется, сигнал
  `cancelled`. SHA-256 считать всегда, в потоке скачивания, и хранить в `actual_sha256`. Таймаут `(5, 120)` закреплён тестом — не менять.
* `UpdateApplier`: параметр `install_after_download : bool = True` (старые тесты и `apply_update_from_release` не меняются).
  При `False` `_on_downloaded`: отмена уже запрошена (отмена в момент окончания) — файл удалить, `cancelled`; иначе удалить
  другие файлы обновлений, записать информационный файл (ошибка записи — предупреждение в журнал, в этой сессии работает),
  сигнал `downloaded(version)`. Новый метод установки готового файла вызывает `_apply_update`.
* `_apply_update_linux`: `prepare_linux_update` удаляет архив в любом случае, поэтому информационный файл убирать и при ошибке,
  и перед запуском скрипта, иначе ссылка повиснет. После сбоя — скачивать заново.
* `AppUpdater`: `load_ready_update()` (очистка + поиск), `download_release(release_data)` (та же версия уже скачана — сразу сигнал,
  без сети; идёт скачивание — пропуск), `cancel_download()`, `is_downloading()`, `install_ready_update()`, сигналы
  `update_downloaded(str)`, `download_cancelled()`.

## Окно (UpdateMixin)

Одно уведомление `update`:

| Состояние | Текст | Кнопки |
|---|---|---|
| доступно | Доступна версия X | Скачать; Страница релиза |
| скачивается | Скачивается версия X, полоса | Отмена |
| отменяется | Отмена… (поток может ждать чтения до 120 с) | нет |
| скачано | Версия X скачана | Установить и перезапустить |
| ошибка | причина | Повторить, если есть `pending_release_data`, иначе Проверить снова; Скрыть |

* `_on_update_available`: версия уже скачана — без вопроса, уведомление «скачано». Иначе прежний вопрос, кнопка «Скачать» вместо
  «Скачать и установить»; отказ — уведомление «доступно».
* Новее скачанной нашлась — уведомление «доступно» про новую. Скачанная лежит, пока новая не докачается.
* При старте `_init_updater` вызывает `load_ready_update()` — независимо от настройки проверки и `PROJECT_MED_NO_UPDATE_CHECK`:
  сети здесь нет.
* «Установить»: `_resolve_unsaved_before_exit()` (обмен с Диском, импорт, незавершённая правка, черновики, старые экраны), затем
  `install_ready_update()`. Вопрос и выход идут в потоке окна подряд, правку между ними не сделать, модальное окно не нужно.
* `_on_update_download_progress` пишет только в уведомление. Общий `progress_bar` не трогать: обмен с Диском может идти одновременно.
* Ошибки — в уведомление, без `QMessageBox`: фоновое окно перехватило бы ввод. Предупреждение «нет контрольной суммы» —
  отдельное уведомление с «Скрыть».
* `_running_task` скачивание не называет: установка предлагается только после него, а закрытие обрабатывается отдельно.
* `closeEvent`: идёт скачивание — вопрос «прервать и выйти?», по умолчанию отказ. Да: `cancel_download()`, окно скрыть и дождаться
  потока. Поток нельзя уничтожать на ходу (процесс упадёт); ждать можно до 120 с, но окно уже закрыто.
* `UpdateProgressDialog`, `update_progress_dialog`, `_close_update_progress` больше не нужны: убрать вместе с их тестами и правкой
  `tests/test_main_window/conftest.py`; сведения — в `interfaces/gui/gui_window/IMPLEMENTATION.md`.
* Если проверка при старте выключена и файла нет — уведомлений нет, всё как раньше.

## Проверить

Без сети, `requests.get` подменён:

* скачивание до конца: файл и информационный файл на месте, установки не было; новый объект `AppUpdater` находит готовое и в сеть не идёт;
